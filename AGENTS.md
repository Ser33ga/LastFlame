# AGENTS.md — Правила разработки Last Flame (Unity 2D URP)

> Архитектурные правила и пайплайн объединяют стандарты проектов `MiniVillains` и `My project (2)`. Читай `SOUL.md` перед любыми изменениями.

---

## 1. Структура проекта (`Assets/Game`)

1. Все создаваемые игровые файлы размещаются строго внутри **`Assets/Game/`** (корень `Assets/` не засоряется).
2. Внутри `Assets/Game/` файлы распределены по типам и логическим группам:
   - `Scripts/` — кодовая база проекта, разделённая на модули с отдельными `.asmdef` и однонаправленными зависимостями.
   - `Sprites/` — 2D-спрайты, тайлсеты, атласы и ассеты от художника (плюс чек-лист готовности `Docs/CHECKLIST.md`).
   - `Prefabs/` — настроенные игровые префабы (коллайдеры, `Light2D`, физика, частицы, сокеты `Socket_Flame`, `FX_Anchor`, скрипты).
   - `Materials/` — 2D URP материалы, `Sprite-Lit-Default` / кастомные шейдеры, Volume-профили.
   - `Textures/` — процедурные и UI-текстуры.
   - `Sounds/` — аудиоклипы, эффекты (огонь, ветер, факел, маяк), эмбиент, настройки микшеров.
   - `Scenes/` — игровые и тестовые сцены (`Boot`, `Gameplay`).
   - `UI/` — верстка интерфейсов, шрифты TMP, таблицы локализации.
3. **Документация `Docs/` в каждой подсистеме**:
   - В каждой ключевой группе находится папка `Docs/` с `README.md` (описание и состав) и `ROADMAP.md` (план работ).
   - Формат записи строки в `ROADMAP.md`:
     `«Фича — Сделана (если да, то дата) — Возможный блокер в будущем»` (блокер — короткой фразой или `—`).
   - Новые фичи в `ROADMAP.md` добавляет только пользователь; агент обновляет статусы, даты и блокеры существующих строк.
   - После изменения файлов группы синхронно обновляются соответствующие `README.md` и `ROADMAP.md`.

## 2. Стек и архитектура кода

1. **Стек:** Unity `6000.6.5f1` (`Universal 2D / URP`), C#.
   - **VContainer** — строгое внедрение зависимостей (`LifetimeScope`, `IInitializable`, `IStartable`, `ITickable`, `IFixedTickable`, `IDisposable`).
   - **UniTask** — асинхронные операции (сцены, фейды, таймеры, финальный ритуал Маяка) без корутин.
   - **PrimeTween** — анимации UI, сквош-стретч свечи, вспышки и переходы.
   - **Unity New Input System** — единый ввод (`IInputService`).
   - **Cinemachine 3.x** — 2D-камера слежения и `Screen Shake` через Impulse.
   - **Localization Package** — локализация UI (никаких hardcoded-строк в интерфейсе).
   - **Addressables** — управление и подгрузка контента при необходимости.
2. **Запрет синглтонов:**
   - Строго запрещены `static Instance`, ленивые синглтоны, создание `GameObject`-менеджеров из кода и `FindObjectOfType` / `FindFirstObjectByType` в игровой логике и сервисах.
   - Связывание выполняется только через `VContainer` `LifetimeScope` и явную передачу зависимостей (`Construct(...)` / `Initialize(...)`).
3. **Жизненный цикл:**
   - `Awake` и `Start` в `MonoBehaviour` не используются для межсервисной логики и поиска зависимостей.
4. **Локализация UI:**
   - Любой отображаемый пользователю текст (кнопки, заголовки, статусы, подсказки) задаётся только через `ILocalizationService` / Localization Package.
5. **Правило `Sprite/Asset → Prefab`:**
   - Сырые спрайты и ассеты не настраиваются вручную на сцене в обход префабов; на их базе собираются префабы в `Assets/Game/Prefabs/`, чтобы обновление арта сохраняло коллайдеры, `Light2D`, сокеты и скрипты.

## 3. Взаимодействие с Unity Editor

- Изменения сцен, префабов, компонентов, настроек рендера и проверки в Play Mode выполняются через официальный Unity CLI / Pipeline (`com.unity.pipeline`) или Unity MCP.
- Прямая ручная правка бинарников, `.meta`-файлов и raw YAML (`.unity`, `.prefab`, `.asset`) в обход Unity строго запрещена.
- Если действие требует ручного шага в редакторе, агент формулирует краткий список шагов и запрашивает подтверждение у пользователя.
- Если у технической задачи несколько вариантов реализации, агент описывает варианты пользователю и запрашивает выбор.
